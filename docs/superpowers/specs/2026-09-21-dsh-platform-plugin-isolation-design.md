# DSH 平台与本地插件隔离

## 目标与交付边界

用户要求基于本次官方升级经验，先完成可隔离的本地功能插件化并构建系统，将无法彻底隔离的部分形成清单讨论。工作基于 `4c63e51` 的隔离候选，不切换原运行目录，不删除自有文件、不迁移真实用户数据。保留旧模块入口，避免现有脚本与测试调用中断。

本轮采用同进程 Cordis 插件与集中平台适配。单纯搬目录无法控制接口变化；立即拆成独立进程又会改变事务、事件顺序和凭据安全边界，因此不属于本轮可直接完成的部分。

## 架构

- 官方子模块保持干净，平台适配层集中官方路径、模块解析、启动、profile 组合和版本契约。
- 本地实现进入 `apps/dsh-agent/src/plugins/{credentials,systems,memory}`。插件经平台 SDK 取得必要的官方类型与服务，业务实现不直接定位官方源码路径。
- 插件注册表声明入口、配置、浏览器资源与启动生命周期。CLI 是组合入口，profile 不再枚举业务实现路径。Trusted Core 仍必须在原生环境快照前消费并清理敏感环境变量。
- Workbench 的官方导入由独立 adapter 模块统一承接；Host 协议与本地工具逻辑不直接解析官方文件。新增模块必须纳入构建 receipt 和 source gate。
- 增加边界/契约检查，发现越层导入、无效插件清单、版本或构建输入漂移时失败，避免把“升级平滑”误解为接受任意不兼容上游。

## 保留能力

保留加密 Vault、进程内浏览器签名、权限隔离、Forge/Data Platform、记忆来源审计、分页、沙箱约束、取消与恢复。旧 `src` 文件作为兼容转发保留。UI 资源保持单份，通过插件资源路径解析。插件共享凭据与事务语义维持原样，不扩展任何权限。

## 无法完全隔离的内容

形成逐项证据清单：事件集合 Set 扩展与旧格式迁移、记忆 surface/agent hook、工具拦截和 sandbox 协议、凭据 provider 替换、浏览器 reserved signing record、Trusted Core 的启动顺序、Web slots/index 插入、Workbench 内部 AgentLoop 及生成物验证。每项给出当前隔离程度、升级检测、短期处理与长期正式扩展接口/附属日志/进程隔离选项。

旧格式日志迁移仍是独立启用阻断：构建成功不等于可打开现有记忆数据，不忽略 required 事件或改写历史 hash。

## 验证与构筑

先验证原路径兼容、插件边界和源码契约，再冻结依赖安装、官方原生构建与 sidecar 构建，更新真实生成清单并验证 source gate。运行原生 profile、credentials、memory、Web 生命周期及浏览器回归。模型调用和真实业务操作不属于无凭据构建验收。

构建会清理本轮生成文件与临时目录，执行前按用户 AGENTS.md 确认具体清理范围；不以新目录规避该要求。未获得清理确认时继续完成所有独立代码及源码检查。
