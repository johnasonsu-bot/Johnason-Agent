# P0 三模式同任务真实验收

状态：**已纳入排期，待 P0 全部任务完成后执行**。来源：2026-09-07 用户要求三个模式运行相同内容，检查是否都能正常完成。本文件是验收要求，不是已执行或通过的证据。

## 1. 验收对象与执行时点

| 模式 | 内部标识 | 验收方式 |
|---|---|---|
| Agent-步进执行模式（Codex Harness） | `python-term` | 正式会话，真实模型调用 |
| Agent-寻路模式（Claude Harness） | `goose` | 正式会话，真实模型调用 |
| Agent-事件驱动模式（DeepSeek Harness） | `dsh` | 正式会话，真实模型调用 |

聊天模式不替代以上任一通道。先完成 P0 已规划的运行时、工具桥与联邦能力，再执行本验收；当前 model-only 的单次或连续文本通过不能提前结项。验收未完成时不将 P0 标记为整体通过，也不以离线 mock 结果替代真实端点。

## 2. 固定可比输入

- 三个模式使用逐字一致的原始任务、相同 Agent 配置、相同 Provider Profile 与实际模型、相同推理参数，以及相同版本的输入文件、Skill/Tool 集合和初始 Workspace 内容。
- 各自新建独立会话和工作副本，避免共享历史、已有产物或上一模式的结果影响后一个模式。记录输入摘要、构建标识和运行时能力；不要求不同运行时的内部事件或生成文本完全一致。
- 模型选择三个运行时共同支持的真实 DeepSeek 云端或本地兼容 API。如果没有共同支持的组合，记为兼容性缺口；不得悄悄换模型、换 Provider 或退回聊天模式后声称可比。
- 从前端发起；使用现有 Vault 保存的凭据。需要解锁/真实调用确认时通过界面提示，不要求用户在聊天或命令中输入密钥。

## 3. 统一任务集

正式执行前冻结完整任务文本及输入包，三模式均使用相同版本，至少覆盖：

1. **文本与持续上下文：** 同一业务写作任务，之后发送逐字相同的追问，确认读取上文并保持上下文。
2. **Agent 与产物：** 使用用户已有场景“@产品经理 写一篇200字小说 @架构师 改写成一个动画html”，比较顺序执行、结构化交接和真实 HTML 产物；不是仅在回复中给出代码块。字数统计规则、HTML 必须包含的内容和交互检查在执行前固定。
3. **工具与恢复：** 相同受控 Workspace 任务，验证真实文件写入/登记/预览，以及取消、重复提交和重启恢复。分别记录结果，不重复覆盖上一次尝试。

上述是共同验收集的最低范围。执行前可按用户实际业务补充任务；不得在看到某个模式失败后仅为该模式降低要求。

## 4. 判定与报告

每个“模式 × 用例”必须记录：任务输入摘要、会话/命令标识、运行时构建、实际 Provider/模型绑定证据、开始/结束时间、终态、人工介入、重试、产物引用、失败原因；证据不包含 API Key 或 Vault 密码。

只有任务要求满足、唯一正确终态、产物存在且可正常打开、历史/上下文可恢复，才记为该项通过。费用/Token/延迟仅在实际可获取时记录；不可获取标明缺失，不估算伪造。不同模型输出措辞无需完全相同，比较依据是相同验收条件。

最终输出三模式横向表，状态分别为：通过、失败、阻塞、未执行。不将跳过/阻塞计为成功；不以某一模式成功授予其余模式通过。所有共同必测项三模式均通过后，才结合其他 P0 门槛评估整体完成；失败项进入缺陷清单并以同一冻结任务复测。
