# 记忆配置启动流程修复

## 根因与边界

历史会话或已经收到消息的会话在配置版本为 0 时，不能补开运行配置。后端的 `MEMORY_NEW_SESSION_REQUIRED` 是已有边界；原页面未显示配置资格，仍允许提交，且项目 ID 为空时缺少本地校验，最终显示泛化错误。

此次未放宽历史会话权限、未导入旧日志、未重跑任务、未修改 Vault，未删除数据。

## 修复

- 配置查询和实际提交共用后端资格判断，返回 `canConfigure` 与 `configurationBlockReason`。
- 未选择会话、历史会话和运行中的会话不能提交；页面说明原因与下一步。
- 项目 ID、工作目录不能为空；预算必须为 128–100000 的整数。无效输入在浏览器内提示。
- 防止同一页面重复提交；会话切换清除旧的分页续读状态。
- 常见后端错误使用固定中文操作指引；版本冲突或运行状态变化后重新读取配置，不自动重试写入。
- 明确区分“创建空会话”和“启用记忆”：创建完成不再暗示配置已经启用。

## 手工测试

1. 打开 `http://127.0.0.1:64356/memory-recovery`。
2. 选择历史会话，应显示解释性通知而不是红色报错，“启用”不可点击，原工作目录仍显示。
3. 填写项目 ID，例如 `changan-project`，核对工作目录、执行覆盖、预算和锚点。
4. 点击“创建新原生会话”，然后点击“启用 / 保存新配置版本”。
5. 确认配置版本为 1、enabled 为 true，三类记忆操作区显示，再点击“打开此会话的原生聊天”发起任务。
6. 新会话不会自动导入旧会话。语义、规程记忆必须有实际写入或提炼来源，不保证每次任务都生成三种记录。
