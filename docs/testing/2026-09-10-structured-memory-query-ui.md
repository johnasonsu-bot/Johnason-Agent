# 记忆结构化查询界面验收

## 本次范围

在 `apps/dsh-agent/public/memory-recovery.html` 复用现有本地 API，新增三个独立查询 Tab；没有修改存储结构、运行时准入、沙箱策略或 Vault。历史未删除，模型任务未重跑。

| 界面 | 已实现 |
| --- | --- |
| 三类记忆 | 情景 / 语义 / 规程分类、关键词查询、摘要表格、来源与正文分层展开、历史版本读取 |
| 语义子图 | 可点击 SVG 节点、类型筛选、完整节点目录、关系表、关联记忆与来源详情 |
| 双时态审计 | UTC 日期时间选择、语义事实与 Effect 快照、有效版本、状态、显式因果边、来源详情 |
| JSON 附件 | 当前查询结果下载，含会话 ID、筛选条件和时间；完整记录单独下载。正文分页和 unpin 回执不会冒充完整记录 |

人工追加 / 确认及原始 JSON 编辑表单保留在折叠的高级区域。查询结果不再直接输出 JSON。正文分页仍可显示原始序列化文本，因为它是实际模型正文页，不是查询结果展示。

## 明确边界

- 类别列表最多加载 100 条；关键词检索先返回最多 100 条再按类别筛选。页面注明并非全库计数。
- 画布最多绘制前 60 个节点；完整节点目录提供其余节点的详情入口，下载保留全部筛选结果。
- 语义图记录来源保留完整记忆内容，节点筛选不裁剪来源正文。
- 双时态查询是给定 validAt / systemAt 的有效状态快照，不是完整状态转换流水；时间留空查询最新。
- Effect 快照最多返回 100 条。普通记忆模式没有受控执行证据时明确显示原因，不伪造两阶段提交或因果关系。
- 页面刷新后查询状态重新加载；切换会话会清除旧详情与下载缓存。

## 用户操作

1. 刷新当前 `/memory-recovery?sessionId=...` 页面，不需要重新解锁或重启服务。
2. 在会话配置下方选择“三类记忆”，选类别，点“查看分类”或输入关键词搜索；“查看详情”打开来源、正文与时间字段。
3. 选择“语义子图”，点“查询 / 刷新子图”，选择节点类型，点击节点或目录中的“查看节点”。
4. 选择“双时态审计”，选语义事实或 Effect，填写 UTC 时间（留空为最新），点“查询审计快照”。
5. 使用各 Tab 的“下载当前查询结果 JSON”；完整记忆详情使用“下载完整记录 JSON”。
