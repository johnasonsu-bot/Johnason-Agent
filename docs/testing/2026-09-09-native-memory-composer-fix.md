# 原生会话记忆入口与沙箱工具清单修复

## 根因

1. 原页面默认把记忆与 required 沙箱绑定。启用后执行守卫拒绝 Bash、Glob 等工具，但模型侧仍可看到这些工具，导致反复调用不允许的路径。
2. 记忆配置入口原先是右下角固定悬浮链接，遮挡原生输入框；不属于当前会话输入区。
3. 原生聊天能读取冷历史，但记忆服务尚未挂载该会话，因此重启后配置读取可能返回 `MEMORY_SESSION_NOT_FOUND`。

## 修复范围

- 普通记忆默认保留原生 DSH 工具、权限与审批。强制沙箱改为独立勾选项，已有 required 策略不降级。
- 按会话约束工具清单；required 会话只向模型提供可执行的记忆工具，并说明 `memory_sandbox_run` 的 argv 用法。执行守卫继续校验旧调用与直接调用。
- 通过原生 `conversation.input.dock` 扩展槽，在新会话及活动会话的输入框上方右侧提供记忆状态、配置、三类记忆入口。不再注入记忆悬浮链接。
- 使用原生品牌扩展槽移除侧栏与首页鲸鱼标志；不修改 pinned DSH 上游源码。
- 冷会话配置读取仅按原生清单中存在的根会话 ID、原目录重新挂载；不提交 prompt、不执行工具、不新建任意 ID。
- 配置按版本保存；其他标签页修改版本后，旧草稿暂停提交，用户刷新后才能继续编辑。

## 操作步骤

1. 打开原生聊天，选择工作区并新建会话。
2. **发送第一条消息前**，点击输入框上方右侧“记忆：未启用”。
3. 填写项目 ID，确认工作目录；默认保持“独立强制沙箱”不勾选。
4. 点击“启用当前会话记忆”，看到“记忆：已启用”后发送任务。
5. 点击“查看三类记忆”，按情景 / 语义 / 规程分类检查来源与版本；页面绑定当前会话。
6. 需要强制沙箱的任务应在启用时单独勾选。已有 required 会话仍使用 `memory_sandbox_run`，不能通过取消勾选放宽权限。

历史未启用的会话仍不能追溯补开配置；不会自动导入旧日志。语义与规程记录必须有实际写入或提炼来源，不保证每轮都产生三种记录。

## 验证边界

- 真实 native HTTP、Chrome、Zstd 历史加载与原生工具/Seatbelt 回归；未自动重跑用户的工作任务，未调用收费模型。
- 主界面覆盖：启用同一会话、刷新恢复、切换另一会话、required 策略不可放宽、多标签版本冲突、窄窗口显示、移除鲸鱼标志。
- 无凭据重置、文件删除、历史删除或上游源码改写。
- 服务更新仍使用原数据目录和端口；重启会锁定 Vault，需要用户在界面用原主密码解锁后才可调用模型。

## 后续修复：重启后的空会话被误判为历史

- 用户报告 `session-4755b630-7551-4013-a9b1-4608681ab7c8` 无法启用。核对原生日志：仅权限初始化与 `session/end-seed`，`blank=true`、0 轮。
- 根因是进程内 `WeakSet` / `firstLiveSeq` 被用作首次启用资格，恢复后丢失“未执行”的判断。
- 改用持久化根会话元数据与未执行事件白名单。重启后的空会话仍可启用；真实用户消息、执行记录、未知事件及 fork/subagent 血缘仍被拒绝。已启用策略不放宽。
- 新增真实 Zstd 历史恢复 + Chrome 主界面启用回归：原会话保存 v1，不新建其他会话，不发起模型或任务。测试先复现失败再通过。
- 全量 120/120 通过，独立复核无阻塞。只更新后台，未刷新用户输入页、未修改其草稿或代发消息。用户在面板点击“刷新状态”后继续启用。
